# 漫画展示排字合同（V5.3）

仅当 G0 的 `typography_profile=comic_display` 时启用。本合同提炼可观察的视觉规则：粗黑字、短行、居中对话、层级明确的锚点文字和可读的对象标签；它不承诺或要求复刻参考图的具体字体、画面构图或故事。

## 责任与关口

- 内容与角色导演在 G0 的显示语义合同中，为每个元素填写 `semantic_role`（`dialogue`、`primary_anchor`、`object_label`、`footer`）与 `reading_priority`。决定每一格是否必须有 `ETF` 标牌、每张果品标签必须显示什么文字、以及重复规则。
- 美术指导在 G1 前交付 `typography-contract-v0.x.json`：可追溯字体文件、SHA-256、使用范围、权利状态和四类文字的视觉样式。无字底图完成后，在实际几何合同中为每项锁定行组和光学偏移。
- 执行场记只生成无字底图并调用确定性排字。不得将字体缩到合同下限之下，不得替换字体、改写行组、删除标签或制造合同外空白 UI。
- 图片总编独立检查适配报告和逐元素裁切证据；字体、字号、行组、居中或占位失败都是 G2 硬失败。

## G0 显示语义扩展

每个元素须明确：容器存在性、逐字文本、对象归属、最大行数、`semantic_role`、`reading_priority` 和重复规则。`required + text_mode=none` 仍只能在明确标记 `blank_container_allowed=true` 并写明原因时使用；否则空白标签是硬失败。

## G1 排字合同

`typography-contract-v0.x.json` 需包含：

- `use_scope` 为 `internal` 或 `commercial`；商业项目的字体 `license_status` 必须是 `confirmed`；
- 字体文件位置、SHA-256、族名与声明字重；文件缺失、哈希不符或商用权利未确认即受阻；
- 四类语义角色的对齐方式、垂直锚点、字重、颜色、描边、最小字号、最小视觉占位与行距；
- 实际几何合同中每个文本元素的 `locked_lines` 与 `optical_offset_px`。拼接后的行组必须与逐字文本完全相等。

字体路径、字形图层、排字报告和适配报告均记录哈希。`--font` 不得覆盖排字合同指定的字体。

## 适配与回退

适配器逐项验证文字蒙版仍在实际安全轮廓内，并在 `comic_display` 额外验证：字体哈希、字重、最小字号、锁定行组、对齐、光学居中与最小视觉占位。任何失败均不交付正式图：容器/容量问题回到美术指导；逐字文案无法容纳时回到内容与角色导演并重开受影响的 G0 字段。
