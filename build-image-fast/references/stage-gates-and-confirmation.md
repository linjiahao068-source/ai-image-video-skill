# 阶段门与确认协议

## 固定状态栏

每轮回复开头使用：

```text
build-image-fast

当前阶段：3/8｜故事与信息结构
阶段状态：待确认
当前版本：story-v0.2

本阶段解决：
[本阶段要消除的关键不确定性]

本阶段产物：
[已完成内容]

需要你确认：
[本轮需要确认的决定]

确认后进入：
[下一阶段名称]
```

只能使用：`未开始 / 进行中 / 待确认 / 已通过 / 需返工 / 受阻 / 已完成`。

## 判断确认

把“确认、OK、通过、采用这个版本、就按这个做”等明确指向当前版本的答复视为确认。不要把只提出新要求、只回答补充问题、“继续看看”“再来一个”“大概可以”或未明确选择推荐项视为确认。

确认后记录具体阶段、版本、锁定项和用户确认。任何修改后生成新版本，不复用旧确认。

## 版本规则

- 阶段 1：`brief-v0.1`
- 阶段 2：`concept-v0.1`
- 阶段 3：`story-v0.1` 或 `info-v0.1`
- 阶段 4：`visual-v0.1`
- 阶段 5：`prompt-route-v0.1`
- 阶段 6：`image-v01`
- 阶段 7：`qa-v0.1`、返修图 `image-v02`
- 阶段 8：`delivery-v0.1`

## 回退与失效传播

| 新条件 | 返回阶段 | 失效的下游 |
| --- | ---: | --- |
| 用途、平台、授权、比例变化 | 1 | 2–8 |
| 核心表达或情绪方向变化 | 2 | 3–8 |
| 事件、信息、文案、CTA变化 | 3 | 4–8 |
| 角色、版式、色板、参考职责变化 | 4 | 5–8 |
| 模型路线、候选数量、提示词变化 | 5 | 6–8 |
| 改选候选 | 6 | 7–8 |
| QA标准变化 | 7 | 8 |

回退时保留历史记录，把下游状态改为 `待重新验证`。

## 图片生成后的续接

内置 `image_gen` 结束回复后，下轮固定从阶段 6 候选确认续接，列出候选版本和四个选择：接受进入 QA、单变量编辑、增加变体、返回阶段 5。用户没有明确选择时不进入阶段 7。

## 阻断状态

精确文字未通过且没有排版工具、公开发布权利未确认、参考素材缺失、精确 CLI/API 缺少凭据或依赖时，使用 `受阻`。说明原因、已完成内容和解除阻断的最小动作，不要越过阻断宣布完成。
