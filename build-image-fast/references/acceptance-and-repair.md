# QA、自动返修与 G2

## QA 在 V5 中的位置

正式图生成后自动执行 QA；不等待用户说“开始 QA”，也不新增“接受 QA”拍板。QA、必要返修、Build Pack、最终文件路径与哈希共同组成 G2 最终交付包。G2 不计入 direct/guided/controlled 的 0/1/2 个正式成图前阻塞拍板。

只有 G2 达到 ready 才能交付。QA 失败时，在有效 standing authorization 范围内自动做单变量返修并重新评分；超出原用途、权利、角色或内容范围时，先让受影响字段和门失效，再回到最早责任门。

## 评分

| 维度 | 分值 | 检查重点 |
| --- | ---: | --- |
| 创意、故事或信息表达准确性 | 25 | 核心表达、因果、顺序、卖点 |
| 构图、层级与阅读性 | 20 | 焦点、阅读路径、安全区 |
| 主体、角色或产品一致性 | 15 | 身份、外观、道具、比例、性格与表演边界 |
| 文字、数据及领域语义准确性 | 15 | 逐字文本、数值、涨跌语义 |
| 风格与视觉完成度 | 15 | 色板、媒介、质感、统一性 |
| 技术规格与交付完整性 | 10 | 尺寸、比例、格式、文件、路径与哈希 |

通过条件：总分 >=85 且没有硬失败。

## 硬失败

- 关键要求、因果、顺序、领域语义或精确文字错误；
- 身份明显漂移、角色串戏、产品/道具归属错误；
- 角色行为违反有效角色合同，或明显偏离有效风格合同；
- G1 候选、candidate_preview 或失效资产被当作 release 输入；
- annotated、contains_text=true 资产或不相关 clean group 被传给正式生成；
- 三件套标签映射、拆分、SHA-256、合同、权利或 registry 资格不一致；
- provenance 缺失、来源类型冒充，或 generated_candidate 被当作用户事实；
- 依赖字段已 invalid / superseded / unknown，却继续生成或交付；
- 版式、安全区、尺寸、格式、最终文件或 Build Pack 不完整；
- 公开/商业发布权利未确认。

硬失败优先于总分。存在任一硬失败时，G2=blocked。

## 自动返修

1. 把失败映射到最早责任字段和门。
2. 保留不受影响字段、来源、G0/G1 版本与 asset release。
3. 用 preserve-change-edit-contract 建立单变量返修合同。
4. 在 standing authorization 有效范围内自动执行返修。
5. 重新运行完整 QA、文件检查和 effective validity 检查。
6. 只有通过后才重建 G2；不追加返修授权、QA 确认或路径确认。

若返修需要改变用途、发布范围、故事、角色职能、权利或 G1 锚点语义，standing authorization 不能替代对应门：G0 字段变化回 G0；controlled 的视觉锚点变化回 G1。

## 责任映射

| 失败 | 最早责任门/字段 |
| --- | --- |
| 用途、故事、信息、文案、角色职能、权利 | G0 |
| controlled 的身份锚点、风格锚点、场景/道具资产、压力测试摘要 | G1 |
| asset release 哈希、审批、拆分或清单错误 | G1 下游自动 release；修复后重算 G1 有效性 |
| 提示词编译、参数、单次生成偏差 | 后台执行字段；不新增用户门 |
| 最终文件、Build Pack、路径或 QA 证据缺失 | G2 |

## G2 ready 条件

- 正式图存在、规格正确并记录 SHA-256；
- QA >=85 且无硬失败；
- direct/guided 的 G0 条件（如适用）仍有效；
- controlled 的 G0、G1 与 asset release 全部有效；
- standing authorization 在本次执行范围内有效；
- 权利、provenance 与 effective validity 无阻断；
- Build Pack 完整记录 workflow、team、gates、authorization、provenance、effective validity、QA 与交付文件。

满足后直接交付 G2，不再要求用户确认 QA 或路径。用户后续提出修改时创建新版本，并只让受影响字段及下游失效。

## V5.2 文字与标签硬门

含显示合同的项目，G2 还必须绑定无字底图、实际轮廓合同、排字构建报告、适配报告，以及逐元素 QA 裁切证据。文字越出容器、进入尾巴/弧边/安全边距、必需标签为空、出现合同外空白 UI、重复元素不满足一致性或 QA 漏检任一显示元素，均为硬失败。先区分是底图容器、几何合同、排字编译还是 QA 证据的问题；不得通过缩写用户锁定文案或静默删除标签来修复。
## V5.3 漫画展示排字硬门

当 typography_profile 为 comic_display，以下任一项属于硬失败：缺少美术指导排字合同；字体文件、SHA-256 或商业权利状态不符；任一元素缺少语义角色、锁定行组或实际几何；字体低于合同下限；对话/锚点未按合同居中；视觉占位不足；适配报告缺少或存在失败的 typography_checks。

失败归因不得交给执行场记自行美化：容器容量、行组或视觉层级问题回到美术指导；逐字文案无法在已确认容量中可读呈现时回到内容与角色导演并重开 G0；单纯构建/文件证据问题由执行场记修复；图片总编独立复核后才恢复 G2。
