# 生成路线选择

`workflow_mode` 决定用户参与多少次；`generation_route` 决定图片如何生成。必须分别记录，不得把“稳定路线”解释为“每一步都要用户确认”，也不得因 `direct` 而忽略生成风险。

## 两条轴

| 轴 | 枚举 | 回答的问题 |
| --- | --- | --- |
| 用户协作 | `atomic / direct / guided / controlled / edit` | 用户需要在哪些高影响决定上拍板 |
| 生成技术 | `fast / stable / edit` | 如何降低当前最主要的生成失败风险 |

例如，精确中文海报通常是 `guided + stable`：只需一次 G0，但后台用稳定路线排字和 QA。授权多角色漫画通常是 `controlled + stable`。明确单变量修图通常是 `edit + edit`。

## 生成路线

| 主要失败风险 | `generation_route` | 执行方式 |
| --- | --- | --- |
| 快速验证氛围或方向，允许非关键漂移 | `fast` | 一次生成完整图，默认 1 张候选 |
| 精确文字、多格顺序、身份、产品、品牌、版式或系列连续性 | `stable` | 先锁适用锚点，再分区/分格生成或确定性后处理 |
| 现有图大部分合格且唯一变更明确 | `edit` | 锁定变更项和保留项，只改目标区域 |

选择路线时记录：主要失败风险、可接受漂移、草稿/精修档、候选数、所需工具、硬门和回退条件。用 `capability-cost-fit` 选最小足够能力档位；用户未授权时不因路线升级自动增加付费候选。

### fast

- 默认 1 张候选，允许非关键装饰、微小姿势或背景细节漂移。
- 不适用于逐字长文案、严格角色/产品身份、多格因果或可复用系列锚点。
- 连续两轮出现文字、身份、分格或版式硬失败时切换 `stable`；同时重新评估是否需把工作流升级为 `controlled`。

### stable

- 按任务建立角色、产品、风格、版式或文字锚点，并使用统一画布、安全区和色板。
- 精确文字优先使用可靠排版或确定性后处理；没有可用工具且模型文字失败时设为 `blocked`。
- 只有 Character 或 Style Fidelity Gate 触发时才强制资产三件套和压力测试；低风险单图使用稳定路线不等于必须建三件套。
- 保真任务以 `candidate_preview 资产＋压力测试 → G1 → 等价重建 release 三件套 → 正式图` 执行。正式图只使用相关无字 clean group，并把 manifest 硬约束编译进文本提示词。

### edit

- 先写唯一变更项、作用范围、必须保持、允许轻微变化和禁止变化。
- 编辑本地图片前先查看目标图；每轮只修一个失败变量并复验保留项。
- 出现第二个实质变更、保留范围不清或身份/构图整体漂移时退出编辑路线，重新选择 `fast/stable`。

## 不改变用户确认数的内部切换

生成路线可以在不产生新业务决定时内部升级：例如 `guided + fast` 因文字失败改为 `guided + stable`，若内容、成本授权和可见设计不变，不重开 G0。只有切换引入新的语义、资产、成本、权利或不可逆视觉取舍时，才打开对应 G0/G1。
