# AI 扩写的控制—探索决策

## R — 原文 (Reading)

## I — 方法论骨架 (Interpretation)

AI 扩写会放大提示词的丰富度，也会放大未写清的自由度。高质量画面不等于符合需求。

因此，在调用扩写前先决定任务模式：**控制模式**服务于规格、品牌、人物、服装或构图等不可变化要求；**探索模式**服务于创意方向、脑暴和惊喜。控制模式先列出不可妥协约束并在输出后验收；探索模式则只保留主题和少量护栏，允许 AI 主动偏离。

## A1 — 书中的应用 (Past Application)

### 案例 1：武侠短提示词的自由扩写

- **问题**：用户把“傍晚、武林大侠、竹林、电影参考”交给 AI 扩写。
- **方法论的使用**：课程比较了扩写后的画面与需求，检查人物年龄和白袍这两个约束。
- **结论**：扩写画面可以很好看，但会遗漏未明确的关键条件。
- **结果**：课程将这种扩写定位为愿意让 AI 自由发挥、寻找灵感时的工具。

### 案例 2：Agent 的操作成本

- **问题**：Agent 可直接执行画布操作与生成，效率提升也伴随资源消耗。
- **方法论的使用**：课程提醒用不好会浪费积分。
- **结论**：让 AI 代做不免除选择与验收责任。
- **结果**：用户应在执行前确认模式与成本，而不是无审查地连续生成。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 想把短提示词交给 AI 扩成长提示词，但担心关键规格被改掉。
2. 需要在品牌合规、产品/人物一致性与大量创意方向之间做取舍。
3. 反馈“AI 扩写的图很漂亮，但不是我要的”。
4. 打算让 Agent 自动生成多个版本，需控制成本与验收方式。

### 语言信号 (用户的话里出现这些就应激活)

- “帮我扩写这段提示词。”
- “我想让它自由发挥，但别改掉这些要求。”
- “扩写后人物/颜色/服装怎么变了？”
- “Should I prioritize creativity or fidelity in prompt expansion?”

### 与相邻 skill 的区分

- 与 `image-prompt-specification` 的区别：后者负责先定义画面要求；本 skill 在已有要求后决定扩写的自由度与验收。
- 与 `reference-image-prompt-reverse-engineering` 的区别：后者从图片提取可验证线索；本 skill 处理生成前后的控制权分配。

## E — 可执行步骤 (Execution)

1. **判定任务模式与成本阈值**
   - 控制模式：有品牌、人物身份、服装、文字、规格或合规等不可变条件；探索模式：目标是找方向、情绪或意外灵感。
   - 完成标准：明确写下“必须保留”与“允许变化”，以及最多生成/迭代次数。

2. **选择扩写自由度并构造输入**
   - 控制模式：把不可变条件放在开头并要求逐项保留；探索模式：只固定主题与少量边界，要求给出多个差异化方向。
   - 完成标准：输入中已标注哪些条件不可变；若没有不可变条件，则明确标为探索。

3. **按约束验收，而非只看美观**
   - 控制模式逐项核查必须条件，不满足则定位遗漏并重写；探索模式按新颖性、可用性和成本筛选方向。
   - 完成标准：输出有通过/不通过结论和下一轮动作；“好看但不符合约束”必须判为控制模式不通过。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户尚未讲清要生成什么：先用 `image-prompt-specification` 建立视觉规格。
- 用户主要目标是从参考图观察并转述可见特征：先用 `reference-image-prompt-reverse-engineering`。
- 任务涉及不可逆的外部执行、付费调用或敏感发布而用户没有授权；应先确认权限与预算。

### 作者在书中警告的失败模式

- 自由扩写虽可产出高质量图像，却会漂移掉“老人”“白袍”等真正关键的约束。
- 把 Agent 当成无需监督的执行者，可能造成积分浪费。

### 作者的盲点 / 时代局限

- 课程未给出可量化的保真度、成本或品牌一致性度量；实际团队应补充验收表与预算上限。
- 不同模型对约束、长提示词与自动 Agent 的遵循度不同，需要按实际平台验证。

### 容易混淆的邻近方法论

- “想要惊喜”不等于“没有底线”：探索模式仍需最小护栏。
- 扩写前的规格化由 `image-prompt-specification` 完成，不能省略。
